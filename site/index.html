01The problem

One target, three consequences —
verified, not assumed.

Before building anything, I reverse-engineered the label. Each consequence below is a test in the repo, and each one shapes everything that follows.

Index-relative ⇒ near zero-mean by construction

The subtraction pins the cross-sectional mean near zero. Predict-zero scores 6.4078 bps and sits within 0.0002 bps of the best constant predictor that exists. It is not a straw man — every number in the project is quoted against it.

tests/test_target_definition.py::test_the_target_is_near_zero_mean_by_construction

The horizon is exactly 6 buckets — not 5, not 7

(Own WAP return − target) collapses to a constant across all 200 stocks at lag 6; at lag 5 or 7 its spread is 691× larger. After s = 480 the horizon leaves the data — those labels can't be re-derived, and that's recorded, not ignored.

tests/test_target_definition.py::test_the_horizon_is_six_buckets_and_not_five_or_seven

All 200 stocks share one index leg

Within a (date, second), the recovered index leg is constant across stocks to σ = 0.005 bps — the data's own quantisation. The weights aren't staged, so the leg is demonstrable but not reconstructible — and it's the second, less obvious reason a date may never be split across folds.

tests/test_target_definition.py::test_target_is_a_60_second_return_minus_a_common_index_leg

Known limitation, stated first: date_id is anonymised and unmapped — 481 integers, no calendar. No regime claims, no event studies, no calendar features. Anything that depends on knowing when these days were is unsupportable and is not claimed anywhere below.

03The baseline

An honest floor: 6.385 bps.

Predict-zero over the 3,293,068 out-of-fold rows. The best constant that exists — the training median — beats it by 0.0002 bps. That is the entire value of knowing the target's location, so every model below is judged by what it adds on top of zero.

05Anatomy of the edge

Where the signal lives —
and the landmark that proves it's real.

The edge is largest at the auction open, holds through the middle, and spikes at exactly s = 300 — the second the exchange first publishes the indicative crossing prices. A bump the model has no way to fake is independent confirmation that near/far_price carry real information. Hover the chart.

The economics: reversion toward the reference price

Two coefficients do the work, sign-stable in all five folds: when the continuous book's WAP is rich to the auction's reference price, the next 60 seconds move relatively down. Everything below the top three is an order of magnitude smaller.

06Null results

The kill list — paid for once, saved from twice.

A log that only contains wins is a marketing document. These are the hypotheses this project measured, killed, and wrote down — each one a Phase-2 temptation that will never waste an afternoon.

Killed · Phase 1

“Yesterday's move persists”

Carrying the previous auction's target — fully legal under the live API — is 42.6% worse than doing nothing: 9.102 vs 6.385 bps. Measured why: cross-auction autocorrelation over 5,226,694 pairs is ρ = 0.027; carrying an uncorrelated value at full weight adds ~√2× the target's own dispersion.

The MAE-optimal shrinkage fitted on train lands at 0.0225 in every fold — the model learns to discard 97.75% of what it's given, for a gain of 0.0022 bps. The entire feature family died for the price of one baseline.

Killed · Phase 2

The revealed-target stream, entirely

Phase 1 killed yesterday's target as a level; Phase 2 killed its scale too. Removing the state family (stock_vol_20d, revealed_abs) leaves the model exactly equal — −0.0002 bps — despite 4.3% of gain importance. The vol state it carries is already spanned by the live book. Killed for Phase 3: any feature whose only input is revealed targets.

Killed

Knowing the target's location

The optimal constant under MAE is the training median (−0.06 bps). It beats zero by 0.00019 bps — the entire value of location information, and the proof predict-zero was never a straw man.

Not dead — just not linear

size_imbalance

Sign-unstable and ≈0 under ridge; 24.2% of total gain under trees. The counterexample that keeps the kill list honest: a null result under one model class is a fact about the pair, not the feature. Spread and near-missing stayed dead under both; this one didn't.

“What none of this licenses: anything about the leaderboard — nothing was scored through the competition API. Anything about regimes — the dates are anonymised. Or that +2.02% is what LightGBM can do — the parameters are deliberately untuned. A tuned number needs a nested split and its own log entry.”

07Engineering

Guards that earned their keep — and the two that caught me.

Everything below exists because a silent failure mode was found, named, and fenced. The last two are bugs in my own work that the discipline surfaced — they're in the log, not hidden from it.

The downcast is gated, not assumed

float32 for the target is accepted only after measuring it: worst row error 1.47e−05 bps (tol 1e−03), zero-MAE shift 2.5e−10 (tol 1e−06). If the gate fails, the target stays float64 and the manifest says so.

scripts/build_fixture.py · manifest.json

The fillna(0) that would have been a catastrophe

far/near_price are null on 55% of rows by construction — no cross exists before the five-minute mark. They live at ~1.0, so fillna(0) silently invents a −10,000 bps deviation. Absence became an explicit indicator + neutral value instead — and indicators are exempt from winsorisation.

src/optiver/features.py · INDICATOR_NAMES

Provenance by manifest, not by trust

The 130 MB fixture is gitignored; what's committed is the manifest — row counts, dtypes, per-column nulls, coverage, the gate numbers, and the parquet's sha256. A rebuild that doesn't reproduce the hash is a rebuild that changed something.

data/fixtures/manifest.json

Randomness forks by label

All randomness flows through seeding.fork("label") — streams fork by name, not call order, so re-running one component can never perturb another's draws. A bare np.random.* is a defect.

src/optiver/seeding.py

The smoke fixture that lied

First built as every-8th-date — which contains no date d−1 for any d, so the carry join returned 100% nulls and three baselines tied at exactly 6.20065 as though it were a measurement. Rebuilt as 8 blocks of 8 consecutive dates; a warning now fires if carry coverage drops below 75%. The failure was silent, plausible, and produced a number — which is exactly why it's in the log.

RESEARCH.md · "build finding"

The coefficient that measured nothing

book_is_missing read exactly 0.000 in all five folds — which looked like an honest null. It wasn't: the outlier clip was flattening a 220-in-5.2M flag to a constant before the model saw it. Found in review, fixed, every number regenerated (headline moved +0.00005), and a synthetic rare-indicator test now guards the whole class.

08Reproduce it

Every number has a named command.

Three scripts produce every figure on this page, each writing a committed, machine-readable report. The tests are green on a fresh clone with no raw data — the committed smoke fixture is the same code path with smaller numbers, never a toy branch.

# fixture + manifest — ONE pass over train.csv, ever
python scripts/build_fixture.py

# the floor, the scorecard, the coefficients   -> reports/phase1_baselines.json
python scripts/run_baselines.py

# ablations, carry autocorrelation, index leg  -> reports/phase1_ablations.json
python scripts/run_ablations.py

# the 2x2 + family ablations                   -> reports/phase2_lgbm.json
python scripts/run_phase2.py --preset FULL --ablate

python -m pytest -q   # 98 passed — seconds, on the committed smoke fixture
